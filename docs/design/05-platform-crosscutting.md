# Student Hub: cross-cutting platform design

This is a read-only design. I read the lims-sotoy conventions (deploy workflows, `db.ts`, auth, rate limiter, backup script, domain folder layout, e2e helpers) and checked current docs through context7:
- zod v4 `toJSONSchema` targets.
- zod-openapi v5 on zod v4 (OpenAPI 3.1).
- The `@scalar/nextjs-api-reference` route handler.
- Expo push limits: 100 messages per send, 1000 ids per receipts call, receipts ready after about 15 minutes and gone after 24 hours, `DeviceNotRegistered`.

Four design points differ from lims-sotoy conventions or from what the lead assumed. Each is marked **FLAW-FIX** (D18, D22, D28, D29).

## 1. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | **Feed is written at publish time.** Publishing an announcement creates one `Notification` row per recipient. The student feed is simply `Notification WHERE userId = me`. | One indexed query, per-item read state, trivial unread count. About 2k rows per announcement is cheap at school scale. |
| D2 | Recipients are resolved **when the announcement is published**: ACTIVE students whose user is active. Students enrolled later do not get old announcements. | Deterministic, auditable (`recipientCount`), and running it twice changes nothing (`@@unique([userId, announcementId])`). |
| D3 | **Push uses a transactional outbox on `Notification.pushStatus`.** Rows are claimed with `UPDATE … ORDER BY … LIMIT` using a claim id. Right after the response, a kick (`next/server after()`) sends them; a cron tick every minute sends anything left. No fire-and-forget. | A push is never lost to a crash, network error or Expo outage. No Redis or queue infrastructure. At-least-once delivery; a duplicate only happens on a crash mid-send. |
| D4 | `expo-server-sdk` sends pushes (chunks ≤ 100, handles 429 backoff). Each accepted ticket is stored in a short-lived `PushTicket` row. Receipts are checked 15 minutes to 24 hours later. `DeviceNotRegistered`, whether on a ticket or a receipt, sets that session's `AuthSession.expoPushToken` to NULL. | Follows Expo's "implement reliably" guidance. |
| D5 | Push goes **only to STUDENT recipients**. Staff and sponsor dashboards poll `GET /notifications/unread-count` every 30 s. No SSE or WebSocket. | Matches the brief ("web dashboards may poll"). A single PM2 process makes long-lived connections pointless. |
| D6 | "Needs review" notifications to admins (leave request, payment proof, ad, top-up) are **merged**: each admin has at most one unread row per type per 60 minutes. | Stops 200 leave requests in a morning from flooding the inbox. The per-domain queue counts stay the source of truth. |
| D7 | Other domains call `notify*(tx, …)` **inside their own business transaction**. | A rolled-back approval never sends a notification. |
| D8 | **Uploading is a separate step.** `POST /api/v1/files` (multipart) returns a `fileId`. Domain endpoints take JSON with the `fileId` and attach the file with a compare-and-set on the new `StoredFile.attachedAt`. | Domain bodies stay JSON validated by zod and documented in OpenAPI. Retries are cheap (for example, a check-in rejected for being outside the geofence can reuse the photo). A cleanup job deletes files that were never attached. |
| D9 | **Storage keys are generated by the server only**: `<bucket>/<kind>/<yyyy>/<mm>/<rand22>.<ext>`. They are parsed with a regex and resolved strictly inside `STORAGE_ROOT`. The public bucket (banners) is served by nginx at `/media/` (a Next route does this in dev and CI). Private files are served only through `GET /api/v1/files/{id}`. | Users never control a path. Banners are cached as immutable. |
| D10 | **File type comes from magic bytes** (`file-type`), never from the client's MIME type or extension. Every image is re-encoded with sharp: rotated upright, metadata (EXIF) stripped, size capped. PDFs are rebuilt with pdf-lib by copying pages into a fresh document and removing `/Annots` and `/AA` from each page. This drops OpenAction, JavaScript, embedded files and AcroForm/XFA. Encrypted PDFs are rejected. PDFs are always served as `attachment`. | Neutralises files that are valid in two formats at once and hidden active content. |
| D11 | Reading a file you may not see returns **404, not 403**. The same rule applies to any cross-school record. | Ids cannot be enumerated across schools. |
| D12 | Every JSON response, including errors, uses `{success, data, error:{code,message,details,requestId?}, meta}`. No 204 responses. The only non-envelope responses are binary file downloads and `/docs`. | One client parser. |
| D13 | Admin tables use **page/limit (limit ≤ 100) with total**. Feeds (inbox, histories) use an **opaque cursor** (`createdAt` + `id`). | Page numbers suit tables. A cursor avoids duplicates and gaps when new items arrive. |
| D14 | **Route contracts are the single source of truth.** A contract holds the zod params, query, body and response schemas, the roles and the error codes. `defineRoute(contract, handler)` validates at runtime; **zod-openapi v5** builds OpenAPI 3.1 from the same contracts. In the test environment every response is also parsed against its contract schema. | Validation and docs cannot drift. zod-openapi handles `$ref` components and `io: input/output`. Plain `z.toJSONSchema` is the fallback if the library ever blocks us. |
| D15 | The docs page uses **Scalar** at `/docs` (a route handler), reading the spec from `/api/v1/openapi.json`. Both are **public in dev and staging, and behind HTTP Basic auth (`DOCS_BASIC_AUTH`) in production**. `docs/openapi.json` is committed and CI checks that it is current. | The client can exercise the API without the full surface map being public. Frontend developers get an offline copy. |
| D16 | Public API is under `/api/v1/*`. Cron uses `/api/internal/*`, which is not versioned and is blocked at nginx. `/api/health` is unversioned. The mobile app sends an `X-App-Version` header; if it is below `MIN_MOBILE_APP_VERSION` the API returns 426 `APP_UPDATE_REQUIRED`. | Store apps cannot be force-updated otherwise. |
| D17 | **CSRF:** cookies are SameSite=Lax. If an `Origin` header is present it must match `APP_ORIGIN`. A POST, PATCH, PUT or DELETE authenticated by cookie must also carry `Origin` or `Sec-Fetch-Site: same-origin`. Bearer requests are exempt. JSON-only bodies (anything else returns 415) force a CORS preflight. No CORS headers are sent. | Browsers always send `Origin` on cross-site POSTs; native apps send Bearer tokens. No token dance needed. |
| D18 | **FLAW-FIX vs lims:** the client IP is taken from `X-Real-IP` set by nginx, and the app listens on `127.0.0.1:3020` only. `X-Forwarded-For` is ignored. | lims uses the first X-Forwarded-For value. Clients can forge it, which bypasses the login rate limiter. |
| D19 | One JSON log line per request: requestId, method, route, status, ms, userId, role, schoolId. Bodies and tokens are never logged. `X-Request-Id` is echoed back, and 500 responses carry only the requestId. Logs are rotated by pm2-logrotate. | Enough to debug without leaking personal data. |
| D20 | **Jobs:** one crontab line calls `POST /api/internal/jobs/tick` every minute with a secret header. The schedule lives in code as a pure function with tests. Queue-type jobs run on every tick and are safe to run twice. Jobs that must run once per school/day/hour are guarded by `JobRun @@unique(job, scopeKey, runKey)`, with compare-and-set retry and takeover of stale runs. **No `GET_LOCK`.** | MariaDB named locks belong to one connection, and the Prisma pool can use a different connection for the release. The schedule ships with the code. |
| D21 | Cron is a **system file (`/etc/cron.d`) with `flock`**, not PM2 cron and not in-process timers. | Survives restarts, never runs twice if the app is scaled, and keeps working while a deploy is building. |
| D22 | **Time.** The process must run with `TZ=UTC`; `instrumentation.ts` checks this at boot and refuses to start otherwise. **FLAW-FIX:** every DB connection sets `time_zone='+00:00'` through the mariadb `initSql` option. School-local time uses fixed offsets (WIB +7, WITA +8, WIT +9; Indonesia has no daylight saving) in a pure module, with no timezone library. | Otherwise `DEFAULT CURRENT_TIMESTAMP` values follow the MariaDB server's timezone and can be off by 7 hours when Prisma reads them as UTC. |
| D23 | **Tests.** Unit tests sit next to the code (`src/**/*.test.ts`, node:test, no DB). Integration tests live in `tests/integration/**/*.test.ts` and run against real MariaDB. Each test builds its own school, users and sponsor, so there is no truncation and files can run in parallel. Jobs that scan the whole database take an optional `scope`. CI gets a fresh DB each run; locally a Docker MariaDB on port 3307 is used, and the scripts refuse any database whose name does not end in `_test`. | Nested Prisma interactive transactions make "roll back after each test" impractical. |
| D24 | Route handlers are tested in-process by calling their exported `GET`/`POST` with a `NextRequest`. Auth reads only `request.headers` and `request.cookies`, never `next/headers`. `after()` is wrapped so tests can run deferred work inline. | Fast, and covers the whole pipeline. |
| D25 | **E2E tests use Playwright's `request` fixture only (no browser)**, against `next start` in CI. | No browser install needed, and it covers the real HTTP stack. |
| D26 | **Coverage uses c8.** It collects V8 coverage across the `node --test` child processes. `all: true`; thresholds: lines, statements and functions 80, branches 75. Coverage is measured over unit plus integration tests. | Mature thresholds and lcov output. Node's built-in `--experimental-test-coverage` is the fallback. |
| D27 | CI has one `gate` job (install with frozen lockfile → typecheck → lint → openapi check → unit → migrate an empty DB → integration with coverage → seed → build → e2e), then `deploy` over SSH. The concurrency group is `deploy-studenthub` with no cancel-in-progress. | DDL interrupted halfway leaves the schema broken (MariaDB DDL is not transactional). |
| D28 | **Deploy runs in place, as in lims:** fetch/reset → frozen install → check the `.env` database name → back up the DB → `migrate deploy` → build (under a VPS-wide `flock`) → `pm2 startOrReload` → poll health **until it reports the deployed git sha**. **FLAW-FIX vs lims:** add `--frozen-lockfile` (lims `deploy.yml` omits it) and the shared build lock. | Proven path. The build lock stops two Next builds (lims and studenthub) from running at 3 GB each at the same time. |
| D29 | **One PM2 process in fork mode.** The rate limiter, impression throttle, job mutex and push kick live in process memory. **FLAW-FIX vs the lead's cluster-agnostic assumption:** do not start PM2 in cluster mode. Scaling later means moving those to the Redis already on the VPS. | Otherwise limits silently weaken per worker. |
| D30 | ESLint enforces the client's rules: `max-lines` 800 (skipping blank lines and comments), `max-lines-per-function` 50 (warn, tests excluded), and `no-console` everywhere except `src/lib/log.ts` and `scripts/`. | Rules checked by the machine, not by memory. |
| D31 | JSON formats: instants as ISO UTC `…Z`; `@db.Date` as `"YYYY-MM-DD"`; money as integer rupiah; Decimal as a JSON number; enums as English codes. `GET /api/v1/meta/enums` returns the Indonesian labels. | Frontends never guess formats. |
| D32 | zod messages are in Indonesian via `z.config(z.locales.id())`. Request bodies use `z.strictObject`, so unknown keys return 400. Query strings are not strict. | Typos in field names fail loudly. |
| D33 | Every service takes `(input, ctx: ActionContext)`, where `ctx` carries `actor`, `now`, `requestId`, `ip`, `userAgent` and `defer`. Pure modules take `now` as a parameter. | Injected clock, audit trail and deferred tasks through one path. |

### H. HTTP pipeline (`defineRoute`)

**H1. Order of steps:**
1. Request id: use `X-Request-Id` if it matches `REQUEST_ID_RE`, otherwise `randomUUID()`.
2. App version: if both `X-App-Version` and `MIN_MOBILE_APP_VERSION` are set and the version is lower, return 426.
3. Auth: `Authorization: Bearer` first, then the access cookie. Other schemes, such as Basic from the docs page, count as anonymous.
4. CSRF check (D17).
5. `mustChangePassword` gate: 403 `PASSWORD_CHANGE_REQUIRED` unless the contract sets `allowPendingPasswordChange`.
6. Role gate: 403 `FORBIDDEN`.
7. Rate limit: 429 with `Retry-After`.
8. Parse path params, query and body with zod: 400 `VALIDATION_FAILED` with `details: [{path, code, message}]`.
9. Run the handler.
10. In the test environment, parse the response with `contract.response`.
11. Wrap in the envelope.
12. Add headers: `X-Request-Id`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`.
13. Run the `ctx.defer` queue through `after()`. In tests (`DEFER_MODE=inline`) the queue is awaited instead.
14. Write the log line.

**H2. Body handling.**
- JSON: the content type must be `application/json`, otherwise 415 `UNSUPPORTED_MEDIA_TYPE`. Bodies over `JSON_BODY_MAX_BYTES` return 413. Unparseable JSON returns 400 `INVALID_JSON`.
- Multipart: `Content-Length` is required (411 `LENGTH_REQUIRED` without it) and must be ≤ `MAX_MULTIPART_BYTES` (413). `formData()` is only called after these checks.

**H3. School scope** (`resolveSchoolScope(actor, requested?)`):

| Caller | `schoolId` query absent | `schoolId` equal to own | `schoolId` different |
|---|---|---|---|
| SCHOOL_ADMIN | own school | own school | 403 |
| SUPER_ADMIN | 400 `SCHOOL_ID_REQUIRED` | n/a | uses the requested school |
| Other roles | 403 | 403 | 403 |

Every school-scoped query filters by the resolved id. A record from another school returns 404.

**H4. Error mapping:**
- `AppError` passes through as is.
- Prisma P2002 → 409 `DUPLICATE` (`details.fields` = constraint target).
- P2025 → 404 `NOT_FOUND`.
- P2034, after `withTx` has retried 3 times → 409 `CONFLICT_RETRY`.
- P2003 → 409 `STATE_CONFLICT`.
- `ENOSPC` → 503.
- Anything else → 500 `INTERNAL_ERROR`, logged with the stack and requestId. The response body never contains stack or SQL.

**H5. Error codes** (`src/lib/http/error-codes.ts`, one registry; OpenAPI lists them). Other domains add their 422/409 codes to the same file.

| Status | Codes |
|---|---|
| 400 | `VALIDATION_FAILED`, `INVALID_JSON`, `INVALID_CURSOR`, `SCHOOL_ID_REQUIRED` |
| 401 | `UNAUTHENTICATED`, `TOKEN_EXPIRED`, `INVALID_CREDENTIALS`, `SESSION_REVOKED` |
| 403 | `FORBIDDEN`, `PASSWORD_CHANGE_REQUIRED`, `CSRF_FAILED`, `ACCOUNT_PENDING_APPROVAL` |
| 404 | `NOT_FOUND` |
| 409 | `DUPLICATE`, `STATE_CONFLICT`, `CONFLICT_RETRY`, `FILE_ALREADY_ATTACHED` |
| 410 | `FILE_PURGED` |
| 411 | `LENGTH_REQUIRED` |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE`, `HEIC_NOT_SUPPORTED` |
| 422 | `BUSINESS_RULE_VIOLATION` plus domain codes, e.g. `NO_RECIPIENTS`, `INVALID_TARGETS`, `ANNOUNCEMENT_NOT_EDITABLE`, `SCHEDULE_OUT_OF_RANGE`, `PUSH_TOKEN_INVALID`, `PUSH_TOKEN_WEB_SESSION`, `FILE_KIND_MISMATCH`, `FILE_TOO_OLD`, `IMAGE_UNREADABLE`, `PDF_ENCRYPTED`, `PDF_INVALID`, `PDF_TOO_MANY_PAGES`, `IMAGE_TOO_SMALL`, and the other domains' `OUTSIDE_GEOFENCE`, `INSUFFICIENT_BALANCE`, … |

**H6. Pagination.**
- Page mode: `page ≥ 1` and `≤ MAX_PAGE`; `limit` 1 to `MAX_PAGE_LIMIT`. A larger limit is rejected with 400, not clamped. Meta is `{total, page, limit, totalPages = ceil(total/limit)}`. When total = 0, totalPages = 0.
- Cursor mode: the cursor is base64url of `{t: ISO createdAt, id}`. Queries use `ORDER BY createdAt DESC, id DESC` with `WHERE (createdAt < t) OR (createdAt = t AND id < id)`. The service fetches `limit + 1` rows to compute `hasMore`. A cursor that cannot be decoded returns 400 `INVALID_CURSOR`.
- Sorting uses a per-endpoint allowlist.

**H7. CSRF (pure `checkCsrf`).**
- Allowed if the method is GET, HEAD or OPTIONS.
- Allowed if the request was authenticated by Bearer, unless an `Origin` header is present and not in `ALLOWED_ORIGINS` (then reject).
- For cookie-authenticated or cookie-setting requests, reject unless `Origin` is in `ALLOWED_ORIGINS` or `Sec-Fetch-Site === "same-origin"`.
- `ALLOWED_ORIGINS = [APP_ORIGIN, ...EXTRA_ORIGINS]`.

**H8. Rate limiter.** Generic `createRateLimiter({max, windowMs, lockMs}, now)` with an injectable clock. It keeps the lims semantics (key `ip::identifier` for login, `userId` for authenticated routes), keyed by the IP from D18.

`data = {screen, id, count?}`. Titles and bodies come from `templates.ts` (Indonesian, pure). Rejections include the `reviewNote`. Money is formatted as "Rp 1.250.000".

N2. **Which rows get a push.** At insert, `pushStatus = PENDING` when the recipient role is STUDENT, otherwise `SKIPPED`. `pushNextAttemptAt` is set to `ctx.now`. If any row is PENDING, the caller runs `ctx.defer(kickPushDispatch)`.

N3. **Body preview.** Collapse whitespace, cut at ≤ `NOTIFICATION_PREVIEW_MAX` characters on a word boundary, then add "…". Cut by code point, never inside a surrogate pair. Bodies are **plain text**: HTML is never rendered, and frontends display them as text.

N4. **Fan-out.** User ids are deduplicated, then written with `createMany({skipDuplicates:true})` in chunks of `FAN_OUT_CHUNK`, all inside the caller's transaction. Only users with `isActive = true` are included.

N5. **Merging admin review notifications.** For merged types:
- Find the recipient's row with the same type, `readAt IS NULL` and `createdAt ≥ now − 60 min`.
- If one exists, run a single atomic statement: `UPDATE Notification SET data=JSON_SET(data,'$.count',CAST(JSON_VALUE(data,'$.count') AS INT)+1), body=?, createdAt=?, updatedAt=? WHERE id=? AND readAt IS NULL`. `createdAt` is moved up so the row returns to the top of the feed.
- If none exists (or the update affected 0 rows), insert a new row with count = 1.
- Two submissions at the same moment may create two rows. That is acceptable.

N6. **Feed filters.** `kind=announcement` → `type='ANNOUNCEMENT'` (index `[userId,type,createdAt]`). `personal` → `type<>'ANNOUNCEMENT'`. `all` → no filter (index `[userId,createdAt]`).

N7. **Unread count** is one statement over index `[userId, readAt]`: `SELECT COUNT(*), SUM(type='ANNOUNCEMENT'), MAX(createdAt) … WHERE userId=? AND readAt IS NULL`. The badge shows "99+" above 99 (client side).

N8. **Mark as read.**
- One item: `updateMany where {id, userId, readAt:null}`. If 0 rows changed, look the item up: not the caller's → 404; already read → 200 with the existing `readAt` (safe to repeat).
- Read-all: `updateMany where {userId, readAt:null, createdAt ≤ before ?? now, kind filter}`. The `before` bound stops it from marking items that arrived after the list was fetched.

N9. **Detail.** Announcement rows include `Announcement.body`. A retracted announcement has no notifications left, so the detail returns 404.

N10. **Low balance.** Pure `crossedBelow(before, after, LOW_BALANCE_THRESHOLD_RUPIAH)` is true when `before ≥ T` and `after < T`. The sponsor domain calls it inside the charge or adjustment transaction. It fires once per downward crossing; a top-up above T re-arms it.

N11. **Retention.** `maintenance-daily` deletes notifications older than `NOTIFICATION_RETENTION_DAYS` in `DELETE … LIMIT 5000` loops. Their PushTickets are deleted by cascade.

### A. Announcements

A1. **Validation** (pure):
- `category ≠ SYSTEM`.
- Title 3–150 characters after trimming; body 1–5000.
- `audience=ALL` → classIds and studentIds must both be empty.
- `CLASSES` → 1 to 50 unique classIds and no studentIds.
- `STUDENTS` → 1 to 500 unique studentIds and no classIds.
- Duplicates are removed before counting.

A2. **Targets must belong to the scoped school.** Classes must be active; students must not be DRAFT. Any foreign or missing id returns 422 `INVALID_TARGETS` with `details.invalidIds`. The message is the same for "does not exist" and "other school".

A3. **Schedule window.** `publishAt` must fall in `[now + 1 min, now + 90 days]`, otherwise 422 `SCHEDULE_OUT_OF_RANGE`. The admin UI shows it in the school's timezone; the API stores UTC.

A4. **Allowed transitions and edits** (pure `assertTransition` / `editableFields`):

| Status | Edit | Allowed actions |
|---|---|---|
| DRAFT | all fields | publish NOW → PUBLISHED; publish SCHEDULE → SCHEDULED; DELETE (hard delete, targets removed by cascade) |
| SCHEDULED | all fields, including `publishAt` | publish NOW early → PUBLISHED; cancel → DRAFT; the due job → PUBLISHED |
| PUBLISHED | title, body and category only; sets `editedAt` and updates the notification rows' title, body and category in one `updateMany` by `announcementId`; **no new push**; changing audience or targets returns 422 `ANNOUNCEMENT_NOT_EDITABLE` | cancel (retract) → CANCELLED: sets `cancelledAt`, deletes that announcement's Notification rows so unsent pushes die with them, writes an AuditLog entry with the reason |
| CANCELLED | none (422) | none; DELETE → 409 |

A5. **Publishing** (`publishInTx(tx, id, ctx)`, shared by the API and the job):
1. Compare-and-set `updateMany where {id, schoolId, status in [DRAFT, SCHEDULED]}` → `status=PUBLISHED, publishedAt=now`. If 0 rows changed → 409 `STATE_CONFLICT` for the API, skip for the job.
2. Resolve recipients (A6).
3. Fan out (N4).
4. Set `recipientCount`.
5. AuditLog `announcement.publish`.
6. `ctx.defer(kick)`.

All of this runs in one `withTx` with the 20 s transaction timeout. For an immediate publish with 0 recipients, the transaction rolls back with 422 `NO_RECIPIENTS`. The job publishes anyway with count 0, since the admin already saw the preview.

A6. **Recipients:**
- ALL: `Student{schoolId, status:ACTIVE, user.isActive}`.
- CLASSES: the same, plus `currentClassId IN targets`.
- STUDENTS: the same, plus `id IN targets`.

The result is a list of `userId`s. `recipient-preview` runs the same query as a count.

A7. **Scheduled job.** `announcements-publish` takes up to `ANNOUNCEMENT_PUBLISH_BATCH` announcements where `status=SCHEDULED AND publishAt ≤ now` (index `[status, publishAt]`). Each gets its own `publishInTx`, so one failure does not block the rest. It runs every tick, so the worst-case delay is about 1 minute.

A8. **Create with mode NOW** does the create and the publish in one transaction. **Create with mode SCHEDULE** sets `status=SCHEDULED`.

A9. **Read stats.** `readCount = COUNT(Notification WHERE announcementId AND readAt IS NOT NULL)` (index `[announcementId]`). Detail view only, never the list.

### P. Push

P1. **Register a token.**
- The session must be live (`revokedAt NULL`, `expiresAt > now`), otherwise 401 `SESSION_REVOKED`.
- Its platform must be ANDROID or IOS, otherwise 422 `PUSH_TOKEN_WEB_SESSION`.
- The token must pass `Expo.isExpoPushToken` and `EXPO_TOKEN_RE`, otherwise 422 `PUSH_TOKEN_INVALID`.
- In a transaction: `updateMany {expoPushToken:token, id≠sid} → null`, then `update {id:sid} → token`. On P2002 retry once. The response is the same whether or not the token was already bound.

Login may also accept an optional `expoPushToken` (auth domain), which calls the same function. Logout, revocation, password change and deactivation set it to NULL (auth domain; already in the schema).

P2. **Dispatch** (`dispatchPendingPushes(jobCtx, {scope?})`). Loop until `PUSH_DISPATCH_BUDGET_MS` is used up or a claim returns 0 rows:
1. **Recover stale claims:** `UPDATE Notification SET pushStatus='PENDING', pushClaimId=NULL WHERE pushStatus='SENDING' AND pushLockedUntil < :now`.
2. **Claim:** `UPDATE Notification SET pushStatus='SENDING', pushClaimId=:cid, pushLockedUntil=:now+lease WHERE pushStatus='PENDING' AND pushNextAttemptAt <= :now [AND userId IN scope] ORDER BY pushNextAttemptAt LIMIT 500`, then `findMany where pushClaimId=:cid`.
3. Rows older than `PUSH_MAX_AGE_MINUTES` → `SKIPPED` ("EXPIRED").
4. Load the recipients' live sessions that have a token. Users with no token → `SKIPPED`.
5. Build messages: `{to, title≤100, body≤178, data:{notificationId,screen,id}, sound:"default", channelId:"default", priority:"high"}`. Chunk them into groups of ≤ 100 and send one after another.
6. Classify each ticket (pure `classifyTicket`):
   - `ok` → insert a `PushTicket`.
   - `DeviceNotRegistered` → `updateMany AuthSession {id, expoPushToken:token} → null`.
   - `MessageRateExceeded`, HTTP 5xx, network error, request-level `TOO_MANY_REQUESTS` → RETRY.
   - `MessageTooBig`, `InvalidCredentials`, other → FAIL. `InvalidCredentials` is also logged at error level as an ops alert.
7. Result per notification (pure `aggregateOutcome`):
   - At least one device ok → `SENT, pushedAt=now`.
   - Else if RETRY and `attempts + 1 < 4` → `PENDING, pushNextAttemptAt = now + [1,5,30][attempts] min`.
   - Else → `FAILED` with `pushError` (≤ 255).
   - Always `pushAttempts += 1` and the claim fields are cleared. The update is guarded by `pushClaimId = :cid`, so a claim that expired meanwhile cannot overwrite a newer one.

P3. **Kick** (`kickPushDispatch`). At most one dispatch runs in the process at a time. If a kick arrives during a run, a flag triggers one more pass afterwards. It is called through `after()` so the HTTP response is never delayed. Cron covers anything the kick misses.

P4. **Receipts** (`push-receipts`, every tick):
- Select PushTickets with `createdAt ≤ now − 15 min` (≤ 1000).
- Call `getPushNotificationReceiptsAsync`.
- `ok` → delete the ticket.
- `error` with `DeviceNotRegistered` → set that session's token to NULL (only if it is still this token), then delete.
- Any other error → log a warning, then delete.
- Tickets older than 24 hours are deleted without a check (Expo has dropped the receipt).

P5. **Transport is chosen by environment** (`PUSH_TRANSPORT`):
- `expo`: production, using `EXPO_ACCESS_TOKEN` if Enhanced Push Security is enabled.
- `log`: dev and staging with no Expo project yet.
- `memory`: tests and CI. Records the messages sent; failures can be scripted.

### S. File storage

S1. **Upload policy** (pure, `UPLOAD_POLICY: Record<FileKind, …>`):

| Kind | Who uploads | Bucket | Accepted input (by magic bytes) | Stored output |
|---|---|---|---|---|
| ATTENDANCE_SELFIE | STUDENT | private | JPEG/PNG/WebP ≤ 4 MiB | JPEG q80, long side ≤ 1280 |
| AD_BANNER | SPONSOR | **public** | JPEG/PNG/WebP ≤ 5 MiB, at least 600×200 | WebP q82, long side ≤ 2048, alpha kept |
| PAYMENT_PROOF | STUDENT | private | image ≤ 8 MiB or PDF ≤ 5 MiB (≤ 10 pages) | image → JPEG q85, ≤ 2000, white background; PDF → rebuilt |
| TOPUP_PROOF | SPONSOR | private | same as PAYMENT_PROOF | same |
| LEAVE_ATTACHMENT | STUDENT | private | same as PAYMENT_PROOF | same |

- HEIC returns 415 `HEIC_NOT_SUPPORTED` with the message "Gunakan format JPEG". The mobile app must convert with `expo-image-manipulator`.
- Empty or unknown types return 415.
- The upload rate limit is 30 per 10 minutes per user.
- `schoolId` (students) or `sponsorId` (sponsors) is taken from the actor, never from the request.

S2. **Image pipeline:**
- Settings: `sharp(buf,{limitInputPixels:MAX_INPUT_PIXELS, failOn:"error"}).rotate().resize({width:max,height:max,fit:"inside",withoutEnlargement:true})`, then encode. No `withMetadata`, so EXIF and GPS are stripped.
- Runs under a semaphore of 4, with `sharp.cache(false)`.
- A decode error returns 422 `IMAGE_UNREADABLE`.
- Re-encoding also neutralises files that are valid in two formats at once (e.g. a JPEG that is also a ZIP or HTML): only newly encoded pixels are written.

S3. **PDF pipeline:**
- The header must start with `%PDF-`.
- `PDFDocument.load` → an encrypted file returns 422 `PDF_ENCRYPTED`; a parse error returns 422 `PDF_INVALID`; more than 10 pages returns 422 `PDF_TOO_MANY_PAGES`.
- Rebuild: `PDFDocument.create()` → `copyPages` → on each page delete `Annots` and `AA` → `save({useObjectStreams:false})`.
- The result is served with `Content-Disposition: attachment`.

S4. **Keys and paths:**
- Key: `${bucket}/${kind-kebab}/${yyyy}/${mm}/${randomBytes(16).base64url}.${ext}`.
- Parse regex: `^(public|private)/(attendance-selfie|ad-banner|payment-proof|topup-proof|leave-attachment)/\d{4}/\d{2}/[A-Za-z0-9_-]{22}\.(jpg|webp|pdf)$`.
- `resolveInsideRoot`: `path.resolve(root, key)` must start with `root + path.sep`, otherwise throw. This rejects `..`, absolute paths, `\`, NUL and a bucket mismatch.

S5. **Local driver:**
- Write to `STORAGE_ROOT/tmp/<rand>` (same filesystem) with `flag:'wx'`, mode 0644 for public and 0600 for private.
- `mkdir -p` the directory with mode 0755 for public and 0700 for private.
- `rename` into place (atomic). `delete` is safe to repeat (ENOENT counts as success).
- Streams use `fs.createReadStream` → `Readable.toWeb`.
- `STORAGE_ROOT` must be outside the app directory in production (checked at boot).

S6. **StoredFile row.** `sha256` is computed over the **stored** bytes, along with width, height and page count. `originalName` is cleaned (basename only, control characters removed, ≤ 255). The upload response never says whether the file is a duplicate. Review screens for admins and super admin show "possible duplicate proof" by joining on `sha256` within the same kind.

S7. **Attaching** (`attachFile(tx, {fileId, kind, ownerUserId, maxAgeMinutes?}, now)`):
- `updateMany where {id, kind, uploadedById: ownerUserId, attachedAt:null, deletedAt:null, createdAt ≥ now−maxAge}` → `attachedAt=now`.
- If 0 rows changed, find out why:
  - no such file, or not the caller's → 404
  - wrong kind → 422 `FILE_KIND_MISMATCH`
  - already attached → 409 `FILE_ALREADY_ATTACHED`
  - too old → 422 `FILE_TOO_OLD`
- Attendance passes `maxAgeMinutes = SELFIE_MAX_AGE_MINUTES`, so a stale selfie cannot be reused.
- Replacing an ad banner calls `detachFile(tx, oldId)` (sets `attachedAt=null`) so the cleanup job can remove the old file.

S8. **Serving files:**
- Public files: `url = PUBLIC_MEDIA_BASE_URL + "/" + key without "public/"`.
- Private files: streamed with the headers listed in the endpoint table.
- Images are served `inline` unless `?download=1`; PDFs are always `attachment`. The file name is `<kind>-<id>.<ext>` (RFC 5987 encoded).
- `GET /files/{id}` for an AD_BANNER redirects 302 to its `/media` URL.

S9. **Who may read a file** (pure `canReadFile(viewer, file)`, returns ALLOW, DENY (→ 404) or GONE (→ 410)):
- The uploader: always.
- SUPER_ADMIN: all files.
- SCHOOL_ADMIN: if `file.schoolId === viewer.schoolId` and the kind is ATTENDANCE_SELFIE, PAYMENT_PROOF or LEAVE_ATTACHMENT.
- SPONSOR member: if `file.sponsorId === viewer.sponsorId`.
- AD_BANNER: any authenticated user.
- Anyone else: DENY.
- A file with `deletedAt` set: GONE, but only after the viewer has passed the ALLOW check.

S10. **Cleanup:**
- `files-orphan-cleanup` (hourly): files with `attachedAt IS NULL AND createdAt < now−24h AND deletedAt IS NULL`, 500 per batch. For each, double-check with NOT EXISTS against the table that would reference that kind (defensive), then delete from disk, then delete the row.
- Selfie retention (in `maintenance-daily`): `kind=ATTENDANCE_SELFIE AND createdAt < now−SELFIE_RETENTION_DAYS AND deletedAt IS NULL`. Delete from disk and set `deletedAt`. The row is kept so the attendance foreign key stays valid; the attendance record stays, and the photo route returns 410.

### J. Jobs

J1. **Tick** (`runTick(now)`): run every due job with `Promise.allSettled`. Each job has its own in-process mutex (a job still running from the last tick is skipped) and stops at the `TICK_BUDGET_MS` deadline. The time of the last tick is kept in memory for `/api/health`.

J2. **Schedule** (pure `dueJobs(now)`):
- Every tick, queue-type (safe to run twice): `push-dispatch`, `announcements-publish`, `push-receipts`, `ads-lifecycle` (calls the sponsor domain's `expireEndedAds(now)` / auto-pause).
- Every tick, keyed per school: `attendance-auto-alpha`. For each active school, run `attendance.runAutoAlphaForSchool(schoolId, localDate, ctx)` once the local time is past `dayEndMinute`. It also catches up the previous `AUTO_ALPHA_CATCHUP_DAYS` dates. Skipping holidays and non-school days belongs to the attendance domain's function.
- Hourly, keyed by UTC hour: `files-orphan-cleanup`.
- Daily, keyed by WIB date, on the first tick at or after 19:00 UTC: `maintenance-daily`. It runs selfie retention, notification retention, and purges AuthSessions revoked or expired more than 30 days ago (refresh tokens deleted by cascade), JobRuns older than 90 days, and PushTickets older than 24 hours.

J3. **Keyed runner** (`runKeyedJob(job, scopeKey, runKey, fn, ctx)`):
1. `create JobRun {status:RUNNING, attempts:1}`.
2. On P2002, load the existing row:
   - SUCCEEDED → skip.
   - FAILED with `attempts < 5` → compare-and-set `updateMany {id, status:FAILED}` → `RUNNING, attempts+1, startedAt=now`.
   - RUNNING with `startedAt < now − 15 min` → compare-and-set on `{id, status:RUNNING, startedAt:old}` (takeover).
   - Otherwise skip.
3. On success: `SUCCEEDED`, `finishedAt`, `result` = counts.
4. On error: `FAILED`, `error` = message up to 2000 characters, logged at error level.
5. After 5 attempts it stays FAILED and is visible at `GET /platform/job-runs`.

J4. **Secret.** `JOB_SECRET` is at least 32 characters. Compare `sha256(header)` with `sha256(secret)` using `timingSafeEqual`. A wrong or missing secret returns **404**. nginx also returns 404 for `/api/internal/`, and cron calls `127.0.0.1:3020` directly.

J5. **Tests.** Jobs that scan the whole database take `scope?: {schoolIds?, userIds?}`. Production passes none.

### T. Time

T1. `localParts(instant, tz)` returns `{ymd, minuteOfDay, weekdayBit}` using `instant + offset`, read with the `getUTC*` methods.

T2. `toDbDate(ymd)` returns `new Date(ymd + "T00:00:00.000Z")`. `fromDbDate(d)` returns `d.toISOString().slice(0,10)`.

T3. `instantAtLocal(ymd, minute, tz)` returns `Date.UTC(...) + minute·60e3 − offset·60e3`.

T4. Sponsor analytics days use `ANALYTICS_TZ = WIB`.

T5. Boot check (`src/instrumentation.ts` `register()`, Node runtime only):
- `process.env.TZ === "UTC"` and `getTimezoneOffset() === 0`.
- The environment passes the zod schema (`JWT_ACCESS_SECRET` ≥ 32, `JOB_SECRET` ≥ 32, `STORAGE_ROOT` exists and is writable, and outside `process.cwd()` in production; `APP_ORIGIN` is a URL; `DOCS_BASIC_AUTH` is required in production).
- `SELECT @@session.time_zone` returns `+00:00`.

Env parsing is lazy (`getEnv()`), so `next build` does not need production secrets.

## 5. Unit and integration test cases

### Unit (`src/**/*.test.ts`)

**http**
- envelope: `ok()` shape; `fail()` shape; `pageMeta` with total 0, 1 and an exact multiple of limit.
- pagination: defaults; limit 101 → issue; page 0 → issue; page > 10000 → issue.
- cursor: round-trip; tampered or non-base64 → `INVALID_CURSOR`; tie on `createdAt` ordered by id.
- prisma-errors: P2002 → DUPLICATE with fields; P2025 → NOT_FOUND; P2034 → CONFLICT_RETRY; P2003 → STATE_CONFLICT; unknown → null.
- csrf: GET always allowed; Bearer POST without Origin allowed; Bearer POST with a foreign Origin rejected; cookie POST without Origin rejected; cookie POST with `Sec-Fetch-Site: same-origin` allowed; cookie POST with an allowed Origin allowed; `Origin: null` rejected.
- request-meta: X-Real-IP used; X-Forwarded-For ignored; invalid X-Request-Id replaced; valid one kept.
- rate-limit: 8 failures lock the key; window expiry resets; lock expires; keys are independent; clock is injected.
- app-version: header missing → allowed; lower than min → blocked; equal → allowed; malformed → blocked; min unset → allowed.
- basic-auth: correct credentials; wrong password; malformed header; non-Basic scheme; compare is timing-safe for equal-length inputs.

**openapi**
- Every contract has a unique `operationId` and `{param}` names that match its params schema.
- Every `route.ts` under `src/app/api/v1` exports exactly the methods that have a contract (file-system scan).
- The generated document passes `@scalar/openapi-parser` validation.
- Every error code a contract lists exists in `ERROR_CODES`.

**time**
- `localParts` at 16:59Z and 17:00Z for WIB (date flips); the same boundaries for WITA and WIT.
- `weekdayBit` for Sunday = 64.
- `instantAtLocal` inverts `localParts`.
- `toDbDate`/`fromDbDate` round-trip.

**money:** `formatRupiah(1250000)` → "Rp 1.250.000"; 0; negative adjustment.

**notifications/rules**
- `previewText`: ≤ 500; word boundary plus ellipsis; emoji at the cut not split; whitespace collapsed; short text unchanged.
- `categoryForType` covers every enum value.
- Deep link for each type.
- `initialPushStatus` for each role.
- `shouldMerge`: unread within 60 min → true; read → false; 61 min old → false; null → false.
- `crossedBelow`: exactly at T; from above to below; already below → false; top-up re-arms.

**notifications/templates:** every template renders non-empty title ≤ 150 and body; rejection includes `reviewNote`; money formatted.

**announcements/rules**
- ALL with targets → error; CLASSES empty → error; 51 classes → error; duplicate ids are removed before counting.
- STUDENTS with classIds → error; SYSTEM category → error.
- `publishAt`: in the past, now + 30 s → error; now + 1 min → ok; now + 90 days + 1 s → error.
- Transition table: every (status, action) pair, including DELETE on PUBLISHED → 409.
- `editableFields(PUBLISHED)` excludes audience.

**push/rules**
- Token regex: `ExponentPushToken[...]` and `ExpoPushToken[...]` accepted; junk rejected.
- `chunk(250, 100)` → 100/100/50; `chunk(0)` → [].
- `buildMessage` truncates title to 100 and body to 178.
- `classifyTicket`: `DeviceNotRegistered`, `MessageRateExceeded`, `MessageTooBig`, `InvalidCredentials`, ok.
- `aggregateOutcome`: one ok plus one failure → SENT; all retry at attempt 3 → FAILED; retry at attempt 1 → PENDING + 5 min; no tickets → SKIPPED.

- Staleness: 60 min cutoff.

### Integration (`tests/integration/**`, real MariaDB)

**platform**
- `SELECT @@session.time_zone` returns `+00:00`.
- A `@db.Date` value `2026-09-21` and a DATETIME value round-trip unchanged.
- A DB-default `createdAt` is within 5 s of `Date.now()`.
- The health route returns 200 with db ok and storage ok.
- `withTx` retries on a simulated P2034 and gives up after 3.
- `lockForUpdate` orders ids.

**http via routes**
- Invalid JSON → 400 `INVALID_JSON`; `text/plain` → 415; unknown body key → 400; oversized body → 413.

- A thrown `Error` → 500 with requestId and no stack in the body.
- A response that does not match its schema fails the test.
- Cookie POST without Origin → 403 `CSRF_FAILED`; Bearer POST → ok.
- `mustChangePassword` user → 403 on a normal route, allowed on change-password.
- Deactivated user → 401.
- `X-App-Version` below the minimum → 426.
- The rate limit returns 429 with `Retry-After`.
- A school admin passing another school's `schoolId` → 403; super admin without `schoolId` → 400.

**announcements**
- Draft, then publish now: notifications go only to ACTIVE students of that school (not DRAFT, INACTIVE, GRADUATED or other schools), and `recipientCount` is correct.

- Scheduled: the job does not publish before `publishAt`, publishes after it, and a second run creates no duplicates.
- Publishing early and the job at the same moment: exactly one wins and notifications are not duplicated.
- Cancel while scheduled → DRAFT; the job skips it.
- Retract after publish → CANCELLED and its notifications deleted (including PENDING pushes); feed and detail return 404.
- Editing a published title updates notification titles and sets `editedAt`, with no new PENDING push; changing audience after publish → 422.
- DELETE draft → gone; DELETE published → 409.
- A school admin reading another school's announcement → 404.
- An AuditLog row is written for publish and retract.

**notifications**
- Cursor feed stays stable while new rows are inserted between pages.
- `kind` filters work.
- Unread counts are split correctly.
- Mark read is safe to repeat; marking another user's notification → 404.
- `read-all` with `before` leaves newer rows unread.
- Merging: a second LEAVE_SUBMITTED within 60 minutes merges (count 2, moved to top); after a read, a new row is created.
- A domain transaction that throws after `notify` leaves no notification rows.
- Staff recipients get `SKIPPED` pushes; students get PENDING.

**push**
- `PUT` binds the token to the session; registering the same token from another user's session moves it; a WEB session → 422; an invalid token → 422; a revoked session → 401.
- `DELETE` clears it.
- Dispatch with the memory transport: 250 recipients → 3 sends (100/100/50).
- A `DeviceNotRegistered` ticket sets the token to NULL.
- A retryable error → PENDING with the next attempt set; after the 4th attempt → FAILED.
- A user with no token → SKIPPED; a 2-hour-old row → SKIPPED.
- Two dispatchers running at once never send the same notification twice.
- A stale SENDING row returns to PENDING after the lease expires.
- Receipts: tickets younger than 15 minutes are ignored; `DeviceNotRegistered` sets the token to NULL (only if it is still that token); checked tickets are deleted; tickets older than 24 hours are removed.
- The kick after an HTTP publish sends without waiting for cron (`DEFER_MODE=inline`).

**files**
- A JPEG selfie with EXIF GPS is stored with no metadata (checked with `sharp().metadata()`), resized, with the right sha256.
- A PNG/HTML polyglot is re-encoded and no longer contains the HTML bytes.
- A PDF with an OpenAction JavaScript is rebuilt without `/JavaScript` or `/OpenAction`.
- Encrypted PDF → 422; an 11-page PDF → 422.
- Too large → 413; no Content-Length → 411; HEIC → 415.
- A student uploading `AD_BANNER` → 403; a sponsor uploading `ATTENDANCE_SELFIE` → 403.
- Download: owner 200 with nosniff, sandbox CSP and the right disposition; another student 404; same-school admin 200; other-school admin 404; super admin 200.
- `attachFile`: attaching the same file twice → 409; another user's file → 404; wrong kind → 422; stale selfie → 422.
- Orphan cleanup deletes files never attached and older than 24 hours (from disk and DB), keeps attached ones, and deletes a replaced banner.
- Selfie retention purges from disk, sets `deletedAt`, the download returns 410, and the attendance row stays.
- The `/media` route serves a public banner; traversal keys and private keys → 404.
- An atomic write leaves no temp file on failure.

**jobs**
- The tick route: no secret → 404; wrong secret → 404; right secret → 200 with results.
- The keyed runner: two concurrent runs for the same key → one runs; a FAILED run is retried on the next tick; a stale RUNNING run is taken over; after 5 failures it stays FAILED.
- `/platform/job-runs` works for SUPER_ADMIN only.
- `maintenance-daily` purges expired sessions and old JobRuns.

### E2E (`e2e/*.spec.ts`, Playwright `request` only, workers 1)
- **Smoke:** health; openapi without Basic auth → 401, with it → 200; the docs HTML loads.
- **Student:** NISN login → forced password change → upload selfie → check in → history.
- **Announcement:** admin publishes to a class → student feed and unread count go up → mark read → count 0; a student in another class does not see it.
- **SPP:** admin creates an invoice → student uploads proof and submits → admin approves → student gets PAYMENT_APPROVED → invoice is PAID.
- **Sponsor:** top-up with proof → super admin approves → balance up → create an ad with a banner → approved → student gets the banner → click → balance deducted.
- **Security:** a cross-school id → 404; a student calling a `/school` endpoint → 403.

## 7. Risks and open questions for the client

1. **Domain name.** Which (sub)domain will serve the API and the docs, and who manages its DNS? Needed for `APP_ORIGIN`, the nginx vhost and SSL, and the mobile app's base URL.
2. **Expo account.** Is there an Expo/EAS account and project for the student app, and who owns it? Push needs the EAS projectId in the app, FCM credentials (Android) and APNs credentials (iOS) uploaded to EAS, and optionally an access token. Until then the server runs with `PUSH_TRANSPORT=log`: inbox notifications still work, just without phone pushes.
3. **Selfie retention (UU PDP; the students are minors).** How many days are selfies kept? The default is 180 days, after which the photo is deleted and the attendance record stays. Payment and top-up proofs are kept indefinitely unless the client says otherwise.
4. **Off-site backups.** DB dumps and uploaded files (selfies, transfer proofs) currently live on the same VPS disk. Is there an off-site target (another server, S3-compatible storage, Google Drive)? Without one, a disk failure loses all payment proofs.
5. **Deploy timing.** Every push to `master` rebuilds in place, which takes about 2–4 minutes during which some endpoints may return errors. Accept deploys at any time, block automatic deploys during the morning check-in peak (for example 05:30–08:00 in each school's local time), or pay the extra complexity of zero-downtime release directories?
6. **Action for the client, not a question:** add the GitHub secrets `VPS_HOST`, `VPS_USERNAME`, `VPS_SSH_KEY` (a dedicated deploy key) and `VPS_PORT` if not 22 to `sedotanbekas/studenthub`, and confirm whether the repo is private.

**Engineering risks**, handled in the design, no client input needed:
- In-memory rate limits and throttles tie the app to one PM2 process (D29).
- pdf-lib is not actively maintained. It is pinned and wrapped behind `pdf.ts` so it can be swapped for a fork or qpdf.
- Expo outages mean delayed or FAILED pushes, but the inbox is unaffected.
- The Scalar page loads its script from the jsdelivr CDN; only the docs page is affected.
- Next 16 route handlers have no body-size limit of their own. It is enforced by the Content-Length checks and by nginx `client_max_body_size 12m`.
