# Kritik adversarial — A2-identity-confirm

Verdict: No blockers. The spec's references all match the code. It changes no API, schema, contract, POLICY or migration, and the existing rules hold: `/student/profile` is scoped to the session, it fails closed, and logout reuses the existing path. Fix one major issue first: the login-page notice copy is inaccurate and leaves out real side effects. Then the minor issues: CSS, tests, and coordination with N1, N3 and A1.

1. **[major]** The NOT_ME login notice misstates how SHARED_DEVICE works. It also tells the borrower to log in on the borrowed phone without saying what that does, which breaks the owner's cause-to-effect copy rule.
   - Bukti: Spec §4 NOT_ME_NOTICE says "HP yang dipakai siswa lain di hari yang sama ditandai". In the code, SHARED_DEVICE only flags attendance rows when two students CHECK IN with the same deviceId on the same date (src/lib/attendance/check-in-service.ts:305-326, lockSharedDeviceRows/flagSharedDevice). Simply using or logging into the phone is not flagged. Logging in with your own NISN on a borrowed phone also has effects the notice does not mention. It revokes the borrower's attendance session on their own phone (src/lib/auth/device.ts:9, "Satu perangkat absen aktif per siswa"). It rebinds Student.deviceBoundAt, so check-ins carry NEW_DEVICE (MEDIUM) for 7 days (src/lib/attendance/anomaly-rules.ts:59,133-134). When the phone's owner logs back in, the borrower's session is revoked again (device.ts:8). In desktop demo, the words "HP ini" are also wrong.
   - Perbaikan: Rewrite NOT_ME_NOTICE to be accurate and give the consequence. For example, title: "Akun sebelumnya sudah keluar dari perangkat ini." Note: "Sebaiknya absen dari HP-mu sendiri. Masuk di sini mengeluarkan akunmu dari HP-mu, dan absen dua siswa dari HP yang sama di hari yang sama ditandai untuk diperiksa admin sekolah." Update test 6 and the PLAN/FRONTEND bullets to match.
2. **[minor]** The login notice as specced will render with the wrong color and a jammed layout.
   - Bukti: Spec §6 renders `<p className="info-message" role="status"><strong/><span/></p>` as a direct child of .login-box, after the intro <p> (src/components/hub/login.tsx:53). `.login-box > p { color: var(--muted) }` (src/styles/shell.css:26) has specificity 0,1,1, which beats `.info-message { color: var(--primary-ink) }` at 0,1,0 (src/app/globals.css:157-158). The notice text comes out muted grey. `.info-message` is also `display:flex; flex-wrap:wrap` (globals.css:157), so the <strong> title and <span> note sit on one line instead of title-over-note. Spec §1 also calls it a one-line explanation, but it has two parts.
   - Perbaikan: Render it as `<div className="info-message login-notice" role="status"><span><strong>{title}</strong><small>{note}</small></span></div>`. Add `.login-notice strong{display:block}` in shell.css, where the login styles live; student.css is the wrong file. Alternatively, raise the selector specificity. Check it in a mobile screenshot (390px).
3. **[minor]** "Ya, ini saya" now triggers the OS location and camera prompts directly, and nothing next to the button says so. On first use, the AccessGate explanation is skipped before the prompt.
   - Bukti: Spec §6: onConfirm runs `onIdentityConfirmed(); void access.request();`. Before this change, the user read AccessGate's explanation (src/components/hub/attendance/access-gate.tsx:19) before tapping the button that calls request() (access-gate.tsx:22). The spec puts a cause-to-effect note under "Bukan saya" but none under the primary CTA. A first-time denial on Safari iPhone can only be undone through Settings (access-gate.tsx:21).
   - Perbaikan: Under "Ya, ini saya", add one short line, e.g. `small.identity-note` "Setelah ini HP meminta izin lokasi & kamera untuk absen." Optionally rename the button "Ya, ini saya · lanjut". The tap count stays the same.
4. **[minor]** The planned browser test for clearing the notice proves nothing, and nothing tests the clearing in login and startDemo.
   - Bukti: Spec §7 new test: after "Bukan saya", it clicks "Masuk demo sebagai Siswa · Bima" and expects the notice count to be 0. Login unmounts as soon as `me` is set (src/components/hub/hub.tsx:101), so the assertion passes even if startDemo never calls setLoginNotice(null). Clearing only matters on the later path where `me` goes back to null without a reason, such as the studenthub:expired handler (src/components/hub/use-session.ts:122), and that path is not covered.
   - Perbaikan: Move the notice transitions into the pure rules file and unit-test them with node:test. For example, `nextLoginNotice(current, event)` with events LOGIN, DEMO, LOGOUT(reason) and EXPIRED. Or extend the browser test: Bukan saya → masuk demo Bima → "Keluar demo" → notice count 0. Also clear loginNotice in the studenthub:expired handler.
5. **[minor]** The updated browser assertions depend on timing. The CI gate does not run them.
   - Bukti: Spec §7 expects the button `/izinkan/i` to be visible right after "Ya". While permissions are pending, the label is "Menunggu izin…", which does not match /izinkan/i (access-gate.tsx:22). The geolocation timeout is 20 s (src/components/hub/attendance/device-access.ts:23) and the default expect timeout is 5 s. If headless geolocation hangs instead of being denied, the test fails. Separately, `test:frontend` (package.json:28) is not a step in .github/workflows/ci-cd.yml, which runs typecheck, lint, openapi:check, unit, int, coverage, build and test:e2e. CLAUDE.md's pre-push list does not include it either. Because a merge to master deploys, broken browser specs would go unnoticed.
   - Perbaikan: Assert on the static AccessGate heading `Nyalakan lokasi dan kamera` (access-gate.tsx:19) or the dialog name "Izinkan perangkat", not the changing button label. Or set the permission state explicitly on the context. In the spec's gate, require running `pnpm test:frontend` locally before merging; it covers both frontend.spec.ts and transitions-webkit.spec.ts via page-slide-scenario.ts.
6. **[minor]** If logout fails completely, the notice still says the account has signed out.
   - Bukti: use-session.ts:163: `api("/auth/logout").catch(() => endServerSession())`. endServerSession swallows its own failure (use-session.ts:67-69). If the phone is offline, the BFF never clears the HttpOnly cookie. `me` is still set to null and loginNotice is set to NOT_ME ("Akun sebelumnya sudah keluar…"), but on reload /auth/me brings back the previous account (use-session.ts:111-113). The spec §9 row for a failed logout only mentions the fallback.
   - Perbaikan: Have logout return or know whether the server session ended. If both calls failed, show a different notice, e.g. "Belum tersambung — akun belum keluar sepenuhnya. Sambungkan internet lalu muat ulang." Or at minimum, document the limitation in §9.
7. **[minor]** If the profile request hangs, the facts line shows "Memuat kelas & NISN…" forever, because there is no timeout.
   - Bukti: The spec's §6 useIdentityFacts falls back to EMPTY_FACTS only when the promise rejects. api() and apiFetch have no timeout or AbortSignal (src/lib/frontend/api.ts:7-16). On slow school networks the placeholder never resolves. The spec §9 claim "placeholder lalu kosong" holds only when the request fails.
   - Perbaikan: Race the fetch against a ~5 s timer, or pass `signal: AbortSignal.timeout(5000)`, and settle to EMPTY_FACTS. Abort it on unmount through the same `active` guard.
8. **[minor]** The type changes are incomplete. HubSession.logout is not listed for a signature change, so a no-op implementation could still pass typecheck.
   - Bukti: Spec §2 changes context.tsx:5 and adds `loginNotice` to HubSession, but does not update `HubSession.logout: () => Promise<void>` (src/components/hub/use-session.ts:81). Because TS allows functions with fewer parameters, the context value at hub.tsx:104 would accept an implementation that ignores `reason`, and typecheck would not catch it.
   - Perbaikan: State this explicitly: `HubSession.logout: (reason?: LogoutReason) => Promise<void>`, with `useCallback(async (reason?: LogoutReason) => …)`. SidebarProps.onLogout and DemoBanner.onExit (frame.tsx:16,77) can stay `() => Promise<void>`, since they call with no arguments.
9. **[minor]** A concurrent logout without a reason can wipe the NOT_ME notice. The guard against double taps relies only on the dialog unmounting.
   - Bukti: With reduced motion or a hidden tab, playLogoutSplash resolves immediately and does not cover the screen (src/components/hub/splash.ts:256-257). During `await api("/auth/logout")` the attendance page is interactive again: the Sidebar or drawer "Keluar dari akun" (frame.tsx:27) can be tapped, and "Absen sekarang" reopens the flow, so "Bukan saya" can fire twice. A second plain logout() sets loginNotice to null. logout has no in-flight guard (use-session.ts:156-167).
   - Perbaikan: Add a `leaving` ref to logout. Ignore calls that arrive while one is in flight, or merge them by keeping the first non-null reason.
10. **[minor]** Merge conflicts with sibling features in the same files are not addressed.
   - Bukti: N1-badge-polling.md:16 makes `unreadBadge.stop()` the first statement of logout and leaveEnvironment (use-session.ts:156-160), which is the same function A2 changes. N5-attendance-reminders.md:147 routes push to `/hub/my-attendance?absen=1`, which the identity gate now covers (good, but not stated). A1 (late reason) will also edit check-in-flow.tsx (title/step logic at :63-73). N3 web push must remove the browser's subscription on any logout, including NOT_ME on a shared phone, or A's reminders keep arriving there. The integration test for logout already deletes Expo push tokens: tests/integration/auth/sessions.test.ts:58.
   - Perbaikan: Add a 'Koordinasi' note: keep N1's stop() first in logout(reason); N3 must unsubscribe on logout(reason) as well; A1 should rebase the title/step changes onto `identityConfirmed`; N5 relies on the gate inside CheckInFlow.
11. **[minor]** Accessibility gaps on the identity card and the login notice.
   - Bukti: The consequence text under "Bukan saya" is not linked to the button, so screen readers announce only "Bukan saya". The mask "••••5432" is read as four 'bullet's. On the login page, `role="status"` content that is present at mount is often not announced, and focus jumps to the autoFocus identifier input (login.tsx:54).
   - Perbaikan: Give the "Bukan saya" button `aria-describedby` pointing at the note's id. Wrap the masked NISN as `<span aria-label="NISN berakhiran 5432">`. Make the notice the form's `aria-describedby`, or put it before the heading.
12. **[minor]** The backlog entry format does not match docs/backlog.md, and the coverage note is slightly inaccurate.
   - Bukti: In docs/backlog.md the 'Tambahan dari implementasi' entries are `###` headings (docs/backlog.md:28-60); the spec proposes a bold bullet. Spec §7 says c8 counts only the new rules file. In fact .c8rc includes all src/**/*.ts with all:true, so src/components/hub/use-session.ts is also counted, with no tests. A2 adds a few more uncovered lines there; the effect is negligible but should be acknowledged.
   - Perbaikan: Use `### Jejak "Bukan saya"` with a short paragraph. In §7, note that use-session.ts is counted and run `pnpm coverage` to confirm the thresholds still hold (lines/statements/functions 80, branches 75).
